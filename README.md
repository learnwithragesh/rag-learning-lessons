# Learn RAG Step by Step: Theory + Practice

A hands-on course on **Retrieval-Augmented Generation (RAG)**, built from scratch in plain Python so every step is visible. No frameworks, no API keys, no cost: everything runs **locally** with [Ollama](https://ollama.com).

Every lesson has:
- 📖 `README.md`: the **theory**, with diagrams, formulas, and the results we measured
- 🐍 `lesson.py`: runnable **practice** code
- 📄 `sample_output.txt`: the output from when the course was built, so you can compare

## ⚙️ Setup

**Requirements** (already present on this machine when the course was built):
- Python 3.10+ with `numpy` (`pip3 install numpy`)
- Ollama running (`ollama serve`) with these models:

```bash
ollama pull nomic-embed-text
```

```bash
ollama pull llama3.1
```

Run **every command from this folder** (the course root):

```bash
cd /Volumes/Learning/RAG/RAG-Learning
```

```bash
python3 01-why-rag/lesson.py
```

> Lesson 4 builds the search index in `data/index/`; Lessons 5 to 7 need it. If you edit the documents or the chunking code, rerun `python3 04-vector-store/lesson.py`.

Swap models with environment variables (no code changes):

```bash
EMBED_MODEL=all-minilm CHAT_MODEL=qwen2.5-coder python3 05-full-pipeline/ask.py
```

(After changing `EMBED_MODEL`, rebuild the index with Lesson 4 using the same variable.)

## 🧠 RAG on one page

```
INDEXING (once)      docs → parse → chunk (+header, +metadata) → embed → vector store (+ BM25 index)
QUERYING (per ask)   question → [rewrite/HyDE] → hybrid search (vector + BM25, RRF) → [rerank]
                     → prompt(rules + numbered passages + question) → LLM → answer + citations
EVALUATING (always)  retrieval: hit@k, MRR  ·  generation: correctness, faithfulness, refusal
```

**The 10 lessons this course demonstrated with real measurements:**

1. LLMs hallucinate on private facts (confidently said "20" days; the truth is 23). RAG grounds them. *(L1)*
2. Embeddings match meaning, not words ("holiday" → "annual leave"), but score margins are small. *(L2)*
3. Focused chunks beat whole documents (0.84 vs 0.68); **context headers** help (0.52 → 0.58). *(L3)*
4. Pure vector search **fails on exact codes** (E-417 ranked 9th of 24). *(L4)*
5. When RAG says "I don't know" wrongly, **check retrieval first**; the LLM was fine. *(L5)*
6. **Measure** retrieval and generation separately. **Calibrate LLM judges**: a bad judge said 0.56, a good one 0.89 for the same system. *(L6)*
7. BM25 catches exact terms; vectors catch paraphrases; **hybrid (RRF) is robust to both**. *(L7)*
8. Only fuse real matches: zero-score keyword results polluted the hybrid ranking. *(L7)*
9. An eval set that reuses document wording is **biased**; include paraphrases. *(L7)*
10. General chat models are coarse rerankers; use dedicated cross-encoders in production. *(L7)*
